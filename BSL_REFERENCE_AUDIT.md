# BSL reference and enhanced rendering

The reference is the checked-in `external/shaders/lib/settings.glsl` default profile, as confirmed by the user. Equation-level checks use the actual GLSL source; there is no matched Minecraft/Iris runtime frame capture. Whole-frame BSL parity is therefore **not established**.

## Implemented source-equation matches

- `src/render/sky/bsl.wgsl` ports default `BSLTonemap` from `program/composite5.glsl`: exposure multiplier 4, symmetric desaturation matrix (0.96/0.94 diagonals, 0.03/0.01 off-diagonals), white curve 2, lower/upper curves 1, inverse saturation matrix, and final [0,1] clamp. The existing linear exposure control composes with that default multiplier. Default vignette strength 1.06 is applied before tone mapping. `BLOXGLOOM_BSL_STYLE=0` selects the previous display/sky styling.
- The same file ports default `GetSkyColor` from `lib/atmospherics/sky.glsl`: custom sky RGB 96/160/255, density day/night/weather 0.35/0.65/1.5, horizon curves 1/1.5, day/night exposure, sun/horizon mixing, squared night palette, rain gradient and ground attenuation. Light and ambient palettes come from the actual default settings and `lib/color/lightColor.glsl`; rain and day/night ambient mixing use its equations.
- `DrawStars` from `lib/atmospherics/clouds.glsl` supplies the default three-noise star mask, world-oriented projection, rain/moon visibility, moon-disc fade and phase-sensitive night palette. Engine presentation seconds supply the bounded frame-time input.
- `GetFogColor` from `lib/atmospherics/fog.glsl` now supplies directional clear/storm fog HDR color in the same source basis as the visible sky. This removes the legacy bright horizon calibration that became white under source tone exposure ×4; enhanced engine fog transmittance remains unchanged. Reference modes additionally port the source Overworld `NormalFog` defaults in `src/render/fog/reference.wgsl`: density 1, night multiplier 4, weather multiplier 1.5, indoor multiplier 1, optical dampening, height 62/falloff 128, and the source variable exponent. Default `FAR_VANILLA_FOG=2` excludes the Overworld, so reference mode does not apply the engine 38–135 m fade. Source `GetFogColor` minimum/exterior and bedrock attenuation are applied with explicit engine eye altitude, bedrock −64 and shelter input. Floating-origin LOD retains absolute eye altitude for the same fog-height equation.
- GPU regression tests compare tone output against an independent double-precision reference, and clear/rain sky against fixed source-equation goldens, and moon-phase night radiance against the squared phase multiplier. Reference air-fog fixtures use independent double-precision GLSL-default goldens for clear/night/rain/indoor/high-altitude extinction and exterior/bedrock color attenuation, and verify relative LOD altitude and scene-transport bypass. These verify the implemented functions, not a complete frame.

## Default materials versus enhanced materials

The checked-in profile comments out `ADVANCED_MATERIALS` and `ALBEDO_METAL`. Run with `BLOXGLOOM_BSL_REFERENCE=1` for the explicit default reference comparison: packed normals, material occlusion, POM, packed PBR, and path-traced GI are disabled. The source forward-lighting branch ports the default raw block-light curve, minimum light, vanilla face diffuse, smooth-lighting square, basic botanical SSS, albedo balancing, emission flattening, desaturation and rain/day/night palettes. Camera uniforms use source custom time warp and the −40° celestial orbit. This is an implemented material/lighting comparison, not whole-frame parity. Default operation retains enhanced rendering.

Run with `BLOXGLOOM_BSL_REFERENCE=advanced` for an explicitly **non-default** artistic-material comparison. It shares the reference orbit/palettes and disables path GI, while enabling packed material detail and BSL's advanced LabPBR remap. The production decoder sets artistic `GetMetalCol` base reflectance, source squared rational complex Fresnel and untinted reflection response (`ALBEDO_METAL` off), including reserved indices' source white fallback. Direct highlight Fresnel uses source `SphericalGaussianFresnel`. The artistic raster sky fallback and SSR subtraction call the same source-sky helper with matching sun/time/rain/moon inputs. Explicitly marked water keeps its separate optical fallback, preventing a second or mismatched subtraction. The actual fragment path preserves source metal lit-albedo treatment and its dielectric Fresnel/smoothness attenuation. The renderer still uses its existing microfacet highlight shape and screen-space reflection infrastructure: finite solar-disc GGX, BSL specular-color remapping, source normal damping, the complete advanced SSS shadow path, and the complete reflection/composite pipeline are not ported or validated as whole-frame equivalents.
The enhanced renderer preserves JG RTX/LabPBR decoding and material detail. Known conductor presets 230–237 now keep albedo tint over the **whole** reflected lobe: normal F0, grazing Fresnel, direct highlights, integrated environment response, reflection metadata and ray-traced sampling. Generic metal continues to use albedo F0 and a white Schlick grazing limit. Preset angular Fresnel now uses the exact unpolarized complex-Snell response rather than Schlick; generic-metal and dielectric paths retain their existing fast Schlick model. Preset direct highlights use height-correlated Smith GGX geometry. Integrated preset environment response uses 16 deterministic GGX visible-normal samples, applying exact angular Fresnel and the matching geometry/PDF ratio. It stays bounded by the material tint even at grazing. GPU angular goldens were independently evaluated with complex s/p reflection amplitudes, and constant-radiance GGX goldens use 16,384 reference samples. The 16-sample environment integral remains finite quadrature, not an exact closed-form BRDF integral.

The complex-Snell response and microfacet sampling follow the primary [PBRT conductor Fresnel](https://www.pbr-book.org/4ed/Reflection_Models/Specular_Reflection_and_Transmission) and [GGX visible-normal/Smith model](https://www.pbr-book.org/4ed/Reflection_Models/Roughness_Using_Microfacet_Theory) references.

Optional advanced BSL behaves differently: `GetMetalCol` uses artistic preset base-reflectance colors, while `ComplexFresnel` uses a simplified rational complex-index angular equation and then squares it. This differs from the enhanced exact complex-Snell response at oblique angles. With `ALBEDO_METAL` disabled it does not apply texture albedo tint. Named `bg_bsl_advanced_preset_base` and `bg_bsl_advanced_complex_fresnel` helpers are wired into the optional advanced runtime decoder/Fresnel path. GPU readbacks verify actual remapped preset F0 is albedo-independent and actual angular/reflection response follows the source equations; enhanced standard-aligned decoding remains separate.

## Actual volumetric clouds

Visible clouds integrate three-dimensional procedural density over a 192–252 m slab, following the supplied non-Iris fallback height 192 and thickness 5 × scale 12. View integration uses 32 density samples at quarter width/height, Beer–Lambert extinction, four solar shadow samples at each occupied step, forward scattering and bounded ambient scattering. RGB stores premultiplied scattered radiance and alpha stores transmittance. A smooth finite-volume horizon fade avoids a hard cutoff at the ray budget. The full-resolution sky reconstructs that radiance/transmittance and applies it to the sky, sun, moon and stars when the scene integrator is unavailable. With ready primary scene transport, the sky draws clear sky/celestial radiance and the cloud raster integration is skipped: the scene integrator supplies the primary camera-path cloud medium once, avoiding duplicate extinction/scattering. The small cloud target still clears for the GPU frame timestamp anchor.

Shared binding-free `bg_sky_environment` integrates eight view/two solar samples for offscreen rays. `bg_cloud_transmittance` provides eight-sample direct-light extinction to the scene integrator. Sky and cloud sampling use the same world-space density and wind drift. Rain strength is a dedicated precipitation input independent of cloud coverage; a dry overcast sky no longer receives the rain palette. Moon phase follows authoritative server world time, one of eight phases per complete world day; the exact BSL multiplier table drives sky and cloud ambient night radiance. Inputs are unattenuated solar radiance; local cloud extinction supplies the shadow rather than a second global weather multiplier. Downward environment rays have no synthetic ground illumination, and zero radiance inputs produce no invented cloud light.

Fire and rain billboards drawn after scene transport now fade their contrast by the same height-dependent air extinction and actual three-dimensional cloud density along the camera-to-particle segment. Cloud-free air uses the analytic integral; cloud segments use the primary medium’s 16/32/16 sample partition. Original emissive RGB is preserved and coverage is multiplied by transmittance, with no second extinction pass over the resolved scene. This is a billboard visibility approximation, not exact absorbing-sheet transport: it does not reconstruct front-segment in-scattering or compute per-particle multiple scattering. When scene transport is unavailable, existing particle blending stays unchanged.

This density is a **new true 3D volume**, not exact BSL cloud-density parity. BSL's supplied `clouds.glsl` builds its volume from `tex/noise.png` and vertically sliced/detail noise with different density and lighting equations. Quarter-resolution reconstruction and bounded sampling can soften fine cloud detail; environment rays use fewer samples than the visible sky. A high-altitude camera can enter the cloud slab.

## Local source-default cloud comparison

The supplied non-Iris fallback is 192–252 m; `CLOUD_HEIGHT=-1` also retains its source 10/73 distance normalization. Submitted camera sample indices explicitly drive the default TAA cloud dither; static preview helpers default to sample zero. The optional reference pass renders at full camera resolution to preserve the source pixel dither lattice; enhanced cloud integration stays at quarter width/height. The reference display history accumulates submitted source-dither samples after bloom, tone mapping, gamma/grain and FXAA. It uses directional camera reprojection for sky, the source five-tap normalized Catmull-Rom kernel, default `0.7 + 0.2 exp(-pixelMotion)` history weight, YCoCg neighborhood AABB clipping and explicit sky-history classification. Every bilinear history tap must belong to sky; foreground, UI/reactive content, camera cuts and unavailable history are rejected. Sky uses its actual unjittered camera direction and cancels terrain raster jitter. Enhanced sky retains its previous current-frame behavior. `BLOXGLOOM_TAA=0` and intentionally single-frame previews still show source dither. Directional rather than finite-far-plane sky reprojection remains an explicit runtime difference. The sky-depth case `z=1` is implemented; BSL's foreground-depth cloud masking, cloud reflection calls and their shortened distance fade are not reconstructed by this pass. Biome fog weights and Iris-provided cloud height remain unavailable. The source enables biome weather, but all default cold/dry/damp fog-density multipliers are 1, so the default cloud fog density is 1.

The original BSL noise PNG is **not bundled or committed**. The supplied shader directory has no license file; the author's [official project terms](https://www.curseforge.com/minecraft/shaders/bsl-shaders) and [license](https://www.curseforge.com/minecraft/shaders/bsl-shaders/license) state All Rights Reserved, allow personal modification, and require permission for redistribution. This is local comparison work against user-supplied inputs, not a redistributable BSL shaderpack. In a reference mode, `BLOXGLOOM_BSL_NOISE=/absolute/path/to/noise.png` selects the local 512×512 RGBA image; absent that variable, `external/shaders/tex/noise.png` is the local default lookup. Missing/invalid input explicitly reports reference clouds unavailable and uses enhanced clouds. The audited supplied input has SHA-256 `5ff93225ed7018e90822824a599e4e080e985fb882fdc15ac9e117dd8ba22a34`, is sampled as linear RGBA8 with repeat/linear filtering, and is not an sRGB artwork texture.

Enhanced true 3D cloud density, direct cloud shadows and path-traced cloud transport remain separate. GPU known-input fixtures use independently constructed constant noise and double-precision density, Bayer dither, opacity and clear/rain/night volume-lighting oracles, with no original BSL asset test dependency. Those fixtures verify the implemented helpers; they do not verify a matched Minecraft/Iris frame. Actual temporal GPU fixtures also exercise moving-camera reprojection, translation/jitter invariance, foreground/sky disocclusion, reactive history rejection and submitted source-dither variance reduction. An opt-in local-input production capture compares the same source sample without accumulation versus 24 submitted sky/cloud/TAA frames.

## Source-default reference albedo transfer

The checked-in terrain/entities/water programs apply `pow(albedo.rgb, 2.2)` to encoded texture RGB after source vertex-color multiplication. The engine's existing material array performs hardware piecewise sRGB decoding. Near default and advanced reference fragments now reverse that hardware transfer and apply the source 2.2 power before PBR/material/surface hooks; enhanced fragments retain their original hardware-linear sample. The alpha component and normal/specular/AO/data channels are unchanged, imported pixels and material IDs are unchanged, and the cutout caster samples use the same conversion to preserve custom surface-hook RGB/alpha decisions. Independent source pixel goldens cover black, the sRGB toe transition, dark/mid RGB and white. Actual `fs_main`/`fs_cutout` consumer fixtures use an unchanged sRGB texture with identity lighting hooks to isolate this transfer, including exact alpha/cutout rejection in default, advanced and enhanced modes. GPU texture decoding itself is implementation-approximated (the tested Metal dark toe differs from ideal sRGB); separate raw-hardware consumer baselines and ideal-linear helper rows distinguish that input precision from the source power equation.

This point-sample conversion does not reconstruct Minecraft/Iris texture filtering: hardware sRGB decode happens before spatial filtering, and the engine creates linear-light albedo mips; source encoded-space filtering followed by the 2.2 power cannot be recovered exactly from an already filtered linear sample. Engine catalog/prebaked tint substitutes for Minecraft biome/per-vertex color and its source multiplication order. Reference actors currently retain hardware-linear texture/palette/customization colors (authored glTF factors are linear). Distant LOD now applies the same source power transfer and forward-lighting/desaturation helpers, including material-aware source sun shadows. Its linear texture/average blend, quantized colors and smooth-lighting proxy remain audited runtime differences. Coarse faces retain material identities while disabling detailed texture samples. Default source water mode replaces the sampled color with its source palette after the texture power; applying this conversion to an already linear source water palette would be incorrect. The separate source-default water branch described below supplies palette replacement, lighting and private sqrt-space compositing.

## Source-default reference bloom

The optional reference modes now use `program/composite4.glsl`/`composite5.glsl` default bloom instead of the enhanced highlight extractor: seven full-scene scales, the separable six-tap weights 0.03/0.15/0.32/0.32/0.15/0.03, source atlas offsets/padding and resolution scaling, fourth-root `/32` encoding, source Bayer8 `/384` dither and RGB8 quantization. Reconstruction filters encoded atlas values before fourth-power `×32` decoding, uses radius-3 weights 4/3.18/2.52/2/1.59/1.26/1 divided by 15.55, and mixes 20% blur with 80% scene color (strength 1, contrast 0). It runs before existing vignette/tone mapping. `DIRTY_LENS` is commented out in the checked-in default and is not applied.

In reference mode any positive bloom control enables the fixed source-default strength; zero disables bloom and the master effects switch still bypasses it. The enhanced renderer keeps its existing strength slider and highlight bloom. No BSL image assets are needed or copied. Explicit HDR box-filtered mips and trilinear sampling replace the OpenGL runtime-generated source mip chain; the engine retains RGBA16F scene precision rather than source R11F_G11F_B10F. Packed atlas RGB channels use the source RGB8 precision (RGBA8 storage with unused alpha). Implicit GLSL source footprint is reproduced with explicit LOD `level + log2(0.8*height/min(720,height))`; exact driver mip generation/filter precision remains an unmatched runtime input. CPU/GPU fixtures compare actual atlas/reconstruction against independent double-precision source calculations with odd dimensions, dim colors, asymmetric HDR emission and tile gutters; separate production-post checks cover black, fixed strength and both disable controls. These equation checks do not establish complete-frame parity. The source-default display sequence is now implemented separately as described below; source-default analytical lens flare is implemented as described below.

## Source-default reference water

Near and distant reference water share the supplied defaults: green-channel counter-moving noise at scales 256 and 48, detail 0.25, sharpness 0.2, four parallax iterations and grazing-dependent normal strength. The local runtime noise is shared with reference clouds and is not bundled. Enhanced water remains separate.

Source-default `REFLECTION=2`, `REFLECTION_MODE=1` enables current-frame water screen-space reflections. Before drawing water, a private pass captures the resolved opaque HDR into source `RGB10_A2` eighth-root encoding with an encoded-space filtered mip chain. Water traces the original opaque depth using the source 30-step, four-refinement march, distance/normal start offset, border fade, geometry mask and fragment mip lookup, then decodes the sampled RGB before Fresnel mixing and specular masking. Sky and local reflected source clouds supply misses. These reflections are shaded before the source square-root alpha blend; the enhanced linear post-water reflection pass receives a zero response for reference water, preventing a second replacement. Water cannot sample its own attachment while it is being drawn.

A private square-root HDR target preserves sorted water layers and is squared back into the linear engine scene afterward. A separate nearest-front depth target starts as a copy of opaque depth and receives reference-only near/LOD water depth writes. The immutable opaque depth continues to serve reflections; the nearest-front target supplies the underwater composite below. Original opaque depth and enhanced water depth behavior remain unchanged. Real authoritative camera voxel classification supplies eye-in-water. In reference mode the water indirect MRT carries the source pre-lighting translucent shaft color, `mix(1, sqrt(base), sqrt(0.7)) * (1 - pow(0.7, 64))`; its explicit water tag remains −2. Reference GI is disabled, and enhanced water retains zero indirect RGB.

Actual GPU fixtures compare source noise/parallax against independently sampled 24-case texture calculations; square-root blending covers zero, one and two layers plus resize. The production reflection helper is checked against an independent source march for geometry/sky masks, border fade, compressed sample decoding and large absolute camera translation. A draw of the actual source-water fragment with the shared near/LOD depth state verifies farther opaque occlusion, nearest water, both layer orders, immutable opaque depth and source translucent shaft color. Engine projection/jitter, voxel lightmap, geometry and HDR scene precision remain runtime differences; encoded mip generation is explicit rather than driver-generated. No matched Minecraft/Iris whole frame has been supplied.

## Source-default reference display and antialiasing

Reference modes now use a dedicated `post/reference_display` path after source bloom/vignette/tone mapping. It applies source `pow(color, 1/2.2)`, the default neutral saturation/vibrance identity, and source blue-channel film grain `(noise−0.5)/256` using the same optional runtime-only local 512×512 noise loader as reference clouds. Missing local noise is explicitly reported and grain is omitted; no original BSL image is embedded. The display intermediate/history uses RGB8 channel precision (RGBA8 storage). The source-default FXAA311 pass follows: edge thresholds 0.125/0.0312, the 12-entry source search schedule and subpixel strength 0.5, halved when submitted temporal accumulation is active.

Source-style display-space TAA follows FXAA. It uses the source five-tap normalized Catmull-Rom construction with `c=0.7`, the 3×3 YCoCg AABB, source motion-dependent `0.7+0.2 exp(−pixelMotion)` history weight, and missing-history four-diagonal bilinear blur at ±0.1667 pixels. The master effects switch retains the engine's explicit bypass contract. Enhanced HDR TAA/post remain unchanged.

History advances only after an encoded display resolve is submitted; acquisition/prepare without a submission cannot invent a previous frame. Source equations are checked independently with actual GPU gamma/grain, sRGB/UNORM transfer, analytic FXAA edges, double-precision Catmull-Rom/motion blending, missing-history blur, sky/foreground rejection and submitted-frame lifecycle fixtures. A matched BSL/Minecraft/Iris frame is still required for whole-frame parity. ## Source-default reference sun shadows

Optional reference modes now select the supplied default 2048-pixel/256-metre sun map and a focused source shadow branch. Terrain and all three actor caster layouts use the same nonlinear XY distortion (default bias 0.9) and source depth compression, with explicit WGPU-to-source depth conversion. Receivers use the nine equally weighted centre/ring taps, source normal-angle/distance bias, botanical blur/bias, raw-coordinate edge fade and skylight gate. Opaque coverage is squared after averaging; basic subsurface coverage uses the source `s × mix(s, 1, subsurface)` rule. This is separate from enhanced blocker-search/PCSS. Point-light caster maps explicitly bypass the nonlinear sun projection through their existing negative sentinel.

The source RGB texture/alpha remap and averaged-color-then-square result are independently expressed and tested with known inputs. Current runtime content has opaque blocks, alpha-cutout plants/leaves and separately rendered fluids, rather than a colored-glass/translucent material class. Accepted leaf texels therefore remain opaque shadow casters; no enhanced biological transmission is substituted for source glass transmission. Runtime opaque-only depth plus RGB transmission attachments are not fabricated from foliage metadata. Water does not enter this map, matching the supplied default with water shadow color and caustics disabled. Fractional alpha remains the engine's 0.5 cutout convention.

The engine supplies its orthographic near/far range, snapped camera-local light view, loaded caster coverage and shared raster caster bias. Sun and local lights currently share caster pipelines, so removing raster bias globally would alter point-light shadows. These are runtime differences from an actual Minecraft/Iris shadow projection and must be assessed with a matched reference frame. Actual colored-glass maps, source advanced-material subsurface shadow sampling and full Minecraft caster classifications are not implemented by this opaque/cutout branch.
